# 对抗式审查循环（Claude Code）

对代码变更执行**迭代式**对抗审查：**审查 → 修复 → 复审 → …**，直到某一轮无阻塞性发现。

本 skill **可修改工作区文件**（仅限修复阶段），但**绝不 commit、绝不 push**——这条由插件 hook 强制，不只是提示词约束。

## 与前代设计的差异（三处，都是刻意的）

1. **没有独立的"验证者"。** 下一轮的 fresh 审查者就是验证者：它重新审**当前完整 diff**，某条发现未被复现即判已修复（**缺席即通过**），被复现即判未修复。少一环，而且验证针对的是真实代码，而不是修复者的说法。
2. **跨模型。** 审查者与修复者是两个不同的模型，绑定写在插件的 `agents/*.md` 里。编排者**不得**在 Agent 调用里传 `model` 参数——它优先级最高，会覆盖角色绑定（等于让被约束者自己挑约束）。
3. **强制而非请求。** 审查者只读由 `tools` 白名单 + 插件级 `hooks/hooks.json` 双重强制；修复者的 commit / push / 破坏性命令由 hook 拦下。

```
代码就绪（coder 或用户）
  ↓
第 k 轮审查（fresh 只读 × N 视角，模型 A）
  ↓ record               ← 内核归一化 / 去重 / 跨轮匹配 / 缺席判定
判定（judge）
  ├ converge → 结束（写报告）
  ├ escalate / hard-stop → 停止并如实报告
  └ continue
      ↓
    修复（fresh 可写，模型 B，最小改动；不 commit）
      ↓
    回到第 k+1 轮审查        ← 下一轮审查承担验证
```

## 不变量

1. **每轮都是 fresh 子代理，无静默降级。** Claude Code 的**非 fork** 子代理本来就不看对话历史，这是宿主原语；因此**禁止 `/subtask` 与 fork**（它们继承上下文，让审查者带着既定结论）。
2. **审查者与修复者必须分离。** 审查者只读；修复者只做最小改动。同一子代理不得既发现又修复（自查偏差）。
3. **状态必须落盘并每轮重读。** 收敛判定只依据状态文件与当前 diff。
4. **绝不 commit / push / 改历史。** 修复只改工作区。
5. **收敛判定必须确定性且显式。** 编排者不得覆盖内核判定；争议项绝不静默合并；未收敛就如实报告未收敛。
6. **修复者的完成声明不可信。** 它是**待验证主张**：不进状态文件，只作为"声称"出现在报告里。
7. **缺席即通过只在视角覆盖完整时成立。** 内核按凭据里的 `lens` 判定覆盖；未覆盖即不关闭、不静默。

## 第 0 步：能力探测、基线与预算

### 0.1 能力探测（**先做**）

| 探测项 | 怎么确认 | 缺失后果 |
|---|---|---|
| **派生能力** | `Agent` 工具可用，`ad-review-loop:reviewer` / `ad-review-loop:fixer` 能派生 | **立即停止**，本 skill 无法执行 |
| **只读强制** | 审查者的 `tools` 白名单生效（Edit / Write / Bash 不在其中） | 降级为提示词约束，报告中标注 |
| **跨模型是否真的成立** | 见下方「三处静默抹平」 | 报告中显式声明"跨模型未达成"，并按降级路径执行 |
| **并发上限** | 默认 20；`CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS` | 降低视角数——**超限是直接报错，不会排队** |

**跨模型的三处静默抹平**（任一命中，跨模型即不成立，必须探测并声明）：

- `CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1` → 忽略所有 agent 的 `model` 字段，单次传参也无效；
- 企业 `availableModels` 白名单 → 被挡的模型**静默回退**到 fallback（只在交互界面提示模型名）；
- `fallbackModel` 链 → 过载时子代理会换模型继续。

**派生凭据（强制）**：每个子代理必须产出一条可核验凭据：`role`（reviewer / fixer / verifier）、`agentId`、`provider`、`fresh`、`lens`、`model`。**无凭据或不完整的子代理视为未执行**——内核在 `record` 阶段丢弃并留痕，不计入预算与覆盖。

### 0.2 预算（**必须先算，不可省**）

| 预算项 | 默认值 | 说明 |
|---|---|---|
| `maxRounds` | **3** | 硬上限。**不要依赖"自然收敛"作为唯一出口**——无硬上限的循环在按 token 计费的宿主上是危险的 |
| 每轮审查者数 | 3（局部）/ 5（高风险：并发、状态机、生命周期、核心路径） | 每视角 1 个 |
| 每轮其他子代理 | 1 个修复者 | 本模式无独立验证者，因此比前代少一个 |
| 总子代理预算 | `maxRounds × (审查者数 + 1)` | 默认 3 × 6 = **18** |

**峰值并发自检**：单轮峰值 = 审查者数 + 1。默认 5 视角时峰值 **6** < 默认上限 20 → ✅ 安全。

### 0.3 建立基线

```bash
mkdir -p .ad-review-loop
node "${CLAUDE_PLUGIN_ROOT}/scripts/loop-state.mjs" init .ad-review-loop/<对象标识>-state.json \
  --target <分支名或对象标识> --baseline <commit 短 hash> \
  --max-rounds 3 --max-subagents 18 \
  --verify-mode absence --stuck-after 2
```

- `--verify-mode absence`：启用缺席即通过（本模式的必需项；缺省是 `explicit`，即必须由独立验证者确认）。
- `--stuck-after 2`：同一发现连续 2 轮未解决即升级人工，不再自动重试。想多给修复者一次机会就设 3（并相应把 `--max-rounds` 提到 4）。

明确"不做什么"：不 commit、不 push、不改基线范围外的文件。

## 第 1 步：循环体

每轮严格按 1.1 → 1.4 顺序执行，**每轮开始前重读状态文件**。

### 1.1 审查（fresh，只读，模型 A）

1. 取**当前**完整 diff（不是上一轮的）：已提交部分 + 未暂存改动 + 未跟踪文件。
2. 并行派生 N 个 `subagent_type: "ad-review-loop:reviewer"`，各分配**一个**视角。每个收到：
   - **完整 diff 原文**（审查者没有 Bash，**必须由你在提示词里贴进去**）
   - 分配视角、证据格式要求、凭据要求
   - "先陈述我理解的范围，再给发现"
3. **所有审查者互不可见**，且**不告知上一轮的任何结论**——包括已修复项。fresh 的含义是彻底 fresh。
4. **不要传 `model` 参数**，也不要传 `permissionMode`（插件子代理会忽略它，靠 `tools` 白名单即可）。
5. 每条发现必须带可点击位置：`<文件路径>:<起始行>-<结束行>`。**无位置的发现直接驳回**（内核会丢弃并留痕）。
6. 给每个审查者一个 `name`（如 `rev-r1-correctness`），它就是凭据里的 `agentId`。

推荐视角（可适配，新增记入状态）：

| # | 视角（`lens`） | 关注点 |
|---|---|---|
| 1 | `correctness` | 逻辑/边界/条件错误；相对旧行为的变化；回归风险 |
| 2 | `concurrency` | 竞态、过期回调、重入、拆除顺序、所有权转移 |
| 3 | `errors` | 缺失错误路径、吞错、超时/重试、空/零/最大输入 |
| 4 | `contract` | API/格式变更、破坏性变更、默认值、兼容性 |
| 5 | `security` | 注入、授权缺口、不安全输入、泄漏、无界增长 |

**跨轮视角集必须一致**：缺席判定依赖它。少跑一个视角，对应发现就不会被关闭（内核留痕，最终升级人工）。

### 1.2 记录（**交给内核，不手工归并**）

把本轮原始输出通过 stdin 交给内核。内核负责归一化、轮内去重、跨轮 id 复用、缺席判定、回归检测：

```bash
cat <<'JSON' | node "${CLAUDE_PLUGIN_ROOT}/scripts/loop-state.mjs" record .ad-review-loop/<对象标识>-state.json
{
  "round": 1,
  "receipts": [
    { "role": "reviewer", "agentId": "rev-r1-correctness", "provider": "agent-tool",
      "fresh": true, "lens": "correctness", "model": "opus" },
    { "role": "fixer", "agentId": "fix-r1", "provider": "agent-tool",
      "fresh": true, "lens": "fix", "model": "sonnet" }
  ],
  "findings": [
    { "lens": "correctness", "severity": "P1", "location": "src/a.ts:10-20",
      "confidence": 92, "triggerPath": "并发写入未加锁", "evidence": "src/a.ts:14" }
  ]
}
JSON
```

- `receipts[].lens` 必须与分配的一致——内核靠它判断下一轮的视角覆盖。
- `receipts[].model` 填 agent 定义里声明的模型；若从 `/tasks` 读到实际运行的模型不一致，**如实填写实际值并在报告中标注**。
- 修复者的凭据与审查者同轮写入（修复发生在下一轮审查之前，但归属上一轮）。

**不要手工做去重或 id 分配**——那正是确定性该覆盖的部分。内核的丢弃与合并全部留痕在 `state.dropped`，报告需呈现。

### 1.3 判定（**唯一出口**）

```bash
node "${CLAUDE_PLUGIN_ROOT}/scripts/loop-state.mjs" judge .ad-review-loop/<对象标识>-state.json
```

内核按固定优先级返回四种判定之一（退出码 1 表示 escalate / hard-stop）：

| 判定 | 触发条件 | 你要做什么 |
|---|---|---|
| `converge` | 本轮无阻塞性发现（全部为 nitpick / 理论风险 / 空） | 结束，写报告 |
| `continue` | 仍有阻塞性发现且未触及其余条件 | 进 1.4 |
| `escalate` | 未裁决争议项 / 检测到回归 / 连续 `--stuck-after` 轮未解决 / 修复引入同级或更严重的新问题 | 停止，如实报告并升级人工 |
| `hard-stop` | 子代理预算耗尽 / 达到 `maxRounds` 仍未收敛 | 停止，如实报告未收敛 |

**编排者不得覆盖内核判定。** 认为判定有误，是修改内核输入（发现数据），不是绕过它。

另外三条**内核无法覆盖、需人工判断**的升级条件：

- 发现需要跨文件架构级改动；
- 问题涉及业务语义，"正确行为"无法从代码或文档判定；
- 修复触及基线范围外的大量文件。

### 1.4 修复（fresh，可写，模型 B，最小改动）

1. 派生 `subagent_type: "ad-review-loop:fixer"` 子代理。按文件邻近度分组：同区域 1 个；独立文件可并行，但**每多派一个就多一份凭据与预算**。复杂问题减并行、串行以便逐个验证。
2. 修复者收到：要修的发现清单（含位置与触发路径）+ 相关文件。**不收到审查者的完整推理，也不收到倾向性描述**——只给事实。
3. 约束：
   - **只做最小化、针对性修改**。不加功能、不重构、不"顺手优化"、不修 nitpick。
   - 修复后若项目有 lint/test，运行；失败需先处理再返回。
   - **绝不 commit / push**（hook 会拦）。
4. 修复者返回每条发现的结果：`fixed（位置）` / `unfixed（原因）` / `false-positive（理由）`。
   **这份声明是待验证主张**：不要 `resolve` 它，不要写进状态文件。它只进报告里的「修复者声称」列。
5. 修复完成 → **直接回到 1.1**。内核在下一轮 `record` 时执行缺席判定：
   - 上一轮出现过、本轮未被复现、且本轮覆盖了它的 `lens` → **判为已修复**；
   - 本轮又被报出 → 未修复；若此前已判修复 → 记为**回归**（升级）；
   - 本轮没覆盖它的 `lens` → 判定不应用、留痕、保持未修复（连续未解决最终会升级，不静默）。

### 1.5 内核不可用时的降级

若无法运行 `node`：手工维护符合 schema 的 JSON，并在报告「宿主能力」一节**显式声明降级**（`收敛判定为手工执行，未经确定性复核`），把 `maxRounds` 降到 2，并**手工执行缺席判定**、逐条列出依据。

## 状态文件

`.ad-review-loop/<对象标识>-state.json`，**每轮重读、每轮覆写**，由内核维护，请勿手工编辑（除降级场景）。

```jsonc
{
  "version": 1,
  "target": "feat/x",
  "baseline": "a1b2c3d",
  "budget": { "maxRounds": 3, "maxSubagents": 18, "subagentsUsed": 6 },
  "rules": { "minConfidence": 70, "dedupeLines": 3, "verifyMode": "absence", "stuckAfterRounds": 2 },
  "findings": {
    "F1": {
      "id": "F1", "lens": "correctness", "severity": "P1",
      "loc": { "file": "src/a.ts", "start": 10, "end": 20 },
      "location": "src/a.ts:10-20",
      "firstSeenRound": 1, "lastSeenRound": 2, "seenRounds": [1, 2],
      "fix": "fixed", "verify": "fixed", "regressed": false,
      "closedBy": { "round": 2, "rule": "absence" },   // 缺席判定的留痕
      "note": "第 2 轮未被复现（缺席判定）；若后续轮次再次出现则记为回归"
    }
  },
  "rounds": [
    { "round": 1, "findingIds": ["F1"], "receipts": [ /* 派生凭据 */ ], "notes": [ /* 轮次备注 */ ] }
  ],
  "dropped": [ /* 每条丢弃与合并都留痕，含 invalid-receipt */ ]
}
```

**为什么必须落盘**：循环会持续多轮，编排者上下文随时可能被压缩或截断。一旦压缩，"这个问题上轮修过吗"就变成猜测，收敛判定随之静默失效。落盘是唯一的宿主通用解药。

## 宿主级坑（Claude Code，实测前不要假设）

- **并发是拒绝不是排队。** 默认 20 个运行中子代理，超限直接失败并提示不要重试；`CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS` 可调。扇出前先按 0.2 算峰值。
- **嵌套默认是允许的（默认 3 层）**，不是禁止。本 skill 是**扁平**的——所以 `reviewer` / `fixer` 的 `tools` 里都移除了 `Agent`。若发现子代理在派生子代理，说明拆分错了。
- **插件子代理会忽略 `hooks`、`mcpServers`、`permissionMode` 三个字段**。所以只读只能靠 `tools` 白名单 + 插件根 `hooks/hooks.json`；不要指望在 agent 文件里写 hooks。
- **插件级 hook 是会话级、启用即生效**，没有 per-skill 范围。我们的守卫按 `agent_type` 收窄，只拦本插件的子代理，不干扰用户日常编辑。
- **插件从 git 市场安装时会被复制进版本化缓存**，插件不能引用自身目录之外的文件。本插件的 `scripts/` 就在插件内，因此安全。
- **`${CLAUDE_PLUGIN_ROOT}` 只在插件内容（skill/命令/agent 文本）里被内联替换，不会进入 Bash 工具的环境变量**。所以在 skill 文本里写 `"${CLAUDE_PLUGIN_ROOT}/scripts/…"` 是有效的，写成 shell 变量 `$CLAUDE_PLUGIN_ROOT` 则不然。
- **改插件不升版本 = 用户看不到变更**。本插件刻意不在清单里声明 `version`，git 源因此以 commit SHA 作缓存键：`git push` 即新版本，无需手工 bump。
- **状态文件不要提交**（`.ad-review-loop/` 应加进被审仓库的 `.gitignore`）。

## 严重度定义

- **P0** — 真实路径上阻塞、数据损坏、崩溃或安全问题。
- **P1** — 明确缺陷，存在绕行方案。
- **P2** — 边界/健壮性问题。
- **nitpick** — 风格偏好；**不参与修复**，仅记录，不影响"干净"结论。
- **理论风险** — 未找到可执行路径；证据出现前不打 P0/P1/P2。

未知严重度由内核保守归一为 `P2`（仍阻塞收敛）。

## 反模式清单（明确禁止）

- ❌ 编排者自己扮演审查者或修复者（违反不变量 1、2）
- ❌ 在 Agent 调用里传 `model` 参数（覆盖角色绑定 = 运行时自选模型）
- ❌ 用 `/subtask` 或 fork 派生审查者（继承上下文 = 不是 fresh）
- ❌ 复用上一轮的审查者，或把上一轮结论告知本轮的 fresh 审查者
- ❌ 让审查者顺手修复，或让修复者审查自己的改动
- ❌ 用 `resolve` 记录修复者的"我修好了"（待验证主张不进状态）
- ❌ 依赖对话记忆做收敛判定，不读状态文件
- ❌ **覆盖或绕过内核的 `judge` 判定**
- ❌ 手工做去重 / id 分配 / 缺席判定
- ❌ 为了少派子代理而裁掉某个视角，然后让内核"缺席即通过"把它关掉
- ❌ 无硬轮次上限、指望"自然收敛"
- ❌ 把争议项当共识通过
- ❌ 修复时加功能、重构、"顺手优化"
- ❌ commit / push / 改历史
- ❌ 为了"跑完"而在子代理失败时跳过它并假装覆盖完整
